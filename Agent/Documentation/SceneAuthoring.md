# Сцена: модели, текстуры и декорации с коллизией

**Кому:** тому, кто заменяет серые коробки на модели, ставит текстуры и добавляет реквизит. Знать домен и геймплей не обязательно.
**Сюда не входит:** форма скульптуры и геометрия лесов (`LevelAuthoring.md`), числа игры (`ConfigReference.md`).

## Главное правило сцены

**Картинка и коллизия идут из одного списка коробок.** Второго списка геометрии в проекте нет и быть не должно: он разъедется при первой правке, и игрок начнёт застревать в воздухе или проваливаться сквозь пол.

Отсюда способ ставить модели: коробка остаётся как коллизия, но помечается невидимой, а на её место кладётся модель. Коллизия и картинка при этом всё равно описаны одной сущностью.

## Что сейчас на сцене и чем рисуется

| Что | Чем рисуется | Файл |
| --- | --- | --- |
| Пол, стены, настилы лесов | `BoxGeometry` + `MeshLambertMaterial`, цвет из `CONFIG.colors` | `src/view/blockout.ts` |
| Опоры-лестницы | То же, цвет `colors.ladder` (сиреневый) | `src/view/blockout.ts` |
| Декорации | То же, цвет `colors.decor` | `src/view/blockout.ts` |
| Глыба | Один `InstancedMesh` на все клетки, собственный `ShaderMaterial`. Мрамор — текстура, скульптура — плоский цвет (после заказа — палитра `.vox`) | `src/view/VoxelRenderer.ts`, `src/view/voxelMaterial.ts` |
| Текстура мрамора | `assets/images/diorite.png`, UV от мировой позиции | грузится в `Game.buildLevel()` |
| Трещины | Атлас, нарисованный на canvas в рантайме | `src/view/crackAtlas.ts` |
| Осколки и пыль | `InstancedMesh` кубиков, цвет `colors.shard` | `src/view/ShardFX.ts` |
| Каркас клетки под прицелом | `EdgesGeometry` + `LineBasicMaterial` — единственная обводка клетки | `src/view/HighlightBox.ts` |
| Свет и фон | `HemisphereLight` + `DirectionalLight`, фон — цвет | `src/view/SceneRoot.ts` |
| Потолка нет | — | — |

**Ловушка со светом.** Глыба рисуется собственным шейдером и **свет сцены игнорирует**: у неё своё направление света в юниформе `uLightDir`. Добавишь лампу — блок-аут и осколки отреагируют, глыба нет. Чтобы поменять свет на глыбе, правь `uLightDir` в `src/view/voxelMaterial.ts`.

Теней нет нигде: `renderer.shadowMap` не включён.

## Масштаб для моделлера

Единица сцены — не метр. Игрок ростом `2.95` единицы, это человек ~1.8 м.

- **Модель сделана в метрах → умножь на 1.64.**
- Стол — примерно `1.2` единицы высотой, дверь — `3.3`, человек — `2.95`.
- Пол лежит на `y = 0`. Глыба `medium` — `3.5 × 6 × 3.5`, `small` — `2 × 3 × 2.5`.
- Комната `24 × 24` единицы, стены до `y = 12`.

Ось вверх — **Y**. У MagicaVoxel вверх Z, у части экспортов FBX тоже — разворачивай в редакторе, а не в коде.

# Часть 1. Модели вместо коробок

## Формат: бери GLB

Решение по формату ещё не принято, поэтому коротко о выборе.

| | GLB (glTF 2.0) | FBX |
| --- | --- | --- |
| Файлов на модель | Один, текстуры внутри | Часто отдельные текстуры |
| Вес и скорость загрузки | Меньше | Больше |
| Загрузчик | `GLTFLoader`, лёгкий | `FBXLoader`, тянет распаковку и NURBS |
| Единицы | Метры, предсказуемо | Часто сантиметры, нужен `scale 0.01` |
| Ось вверх | Y, как у нас | Зависит от экспортёра |

**Рекомендация: GLB.** FBX оправдан только если модели уже приходят в нём и переэкспорт невозможен.

## Куда класть файлы

```
assets/images/*.png        # текстуры, которые импортирует Vite (сейчас diorite.png)
assets/vox/*.vox           # MagicaVoxel, читает плагин в vite.config.ts
public/models/*.glb        # модели без обработки Vite
public/textures/*.png      # если нужен путь вида /textures/... без импорта
```

`assets/` Vite обрабатывает: `import url from '../../assets/images/diorite.png'` даёт хешированный URL. Всё, что лежит в `public/`, отдаётся с корня как есть: `public/models/crate.glb` → `/models/crate.glb`.

## Загрузчик, которого пока нет

В проекте нет ни одного загрузчика моделей — их незачем было добавлять. Когда понадобится, создай `src/view/models.ts` ровно с таким содержимым:

```ts
import * as THREE from 'three';
import { GLTFLoader } from 'three/examples/jsm/loaders/GLTFLoader.js';
import type { Aabb } from '../domain/Aabb';

const loader = new GLTFLoader();

/** Модели грузятся асинхронно. Коллизия к этому моменту уже стоит, поэтому геймплей не ждёт. */
export async function loadModel(url: string): Promise<THREE.Object3D> {
  const gltf = await loader.loadAsync(url);
  return gltf.scene;
} 

/**
 * Вписывает модель в коробку коллизии: центрирует по X и Z, ставит на её низ
 * и масштабирует до её габаритов. Так модель гарантированно совпадает с препятствием.
 */
export function fitToBox(object: THREE.Object3D, box: Aabb): void {
  const bounds = new THREE.Box3().setFromObject(object);
  const size = bounds.getSize(new THREE.Vector3());
  const scale = Math.min(
    (box.maxX - box.minX) / size.x,
    (box.maxY - box.minY) / size.y,
    (box.maxZ - box.minZ) / size.z,
  );
  object.scale.setScalar(scale);

  const scaled = new THREE.Box3().setFromObject(object);
  object.position.x += (box.minX + box.maxX) / 2 - (scaled.min.x + scaled.max.x) / 2;
  object.position.z += (box.minZ + box.maxZ) / 2 - (scaled.min.z + scaled.max.z) / 2;
  object.position.y += box.minY - scaled.min.y;
}
```

Для FBX вместо этого: `import { FBXLoader } from 'three/examples/jsm/loaders/FBXLoader.js'`, и `loadAsync` возвращает готовый `Object3D` без `.scene`. Дополнительных пакетов ставить не надо.

## Рецепт: заменить пол, стену, настил или лестницу моделью

Пример для пола.

### Шаг 1. Скрыть серую коробку, оставив коллизию

В `src/domain/levels/arena.ts` найди строку, которая создаёт нужную коробку, и добавь флаг:

```ts
boxes.push({ ...box('floor', -a, -p.plateThickness, -a, a, 0, a), invisible: true });
```

Флаг `invisible` читает только `blockout.ts`: коробка перестаёт рисоваться, но остаётся в коллизии, в границах и в тестах досягаемости.

### Шаг 2. Положить модель на место коробки

В `src/app/Game.ts`, в конце конструктора:

```ts
const floor = this.arena.boxes.find((b) => b.kind === 'floor');
if (floor) {
  void loadModel('/models/floor.glb').then((model) => {
    fitToBox(model, floor);
    this.sceneRoot.scene.add(model);
  });
}
```

### Шаг 3. Проверить

```
npm test          # коллизия не изменилась, тесты обязаны быть зелёными
npm run dev
```

Если модель не совпала с препятствием — проблема в модели, а не в коде: правь габариты в редакторе. Подгонять коллизию под модель нельзя, коллизия задана раскладкой арены.

**Про лестницу отдельно.** Её сиреневый цвет — не украшение: это единственная интерактивная геометрия арены, и она обязана читаться как «сюда можно залезть». Заменяя её моделью, оставь ей визуальное отличие от остальной арены, иначе игрок не найдёт путь наверх.

## Рецепт: добавить потолок

Потолка нет. Добавляется одной коробкой в `createArena`, рядом со стенами:

```ts
boxes.push(box('structure', -a, p.wallTop, -a, a, p.wallTop + w, a));
```

Проверь после этого `npm test`: потолок ниже прыжка с настила сделает часть верхней грани глыбы недостижимой, и тест досягаемости это поймает.

# Часть 2. Декорации с коллизией

## Где их добавлять

Единственное место — `src/domain/levels/props.ts`. Массив `DECOR` попадает в `arena.boxes`, то есть сразу и в картинку, и в коллизию, и в тесты.

```ts
import { decorBox } from './props';

export const DECOR: ArenaBox[] = [
  // ящик у стены: 1×1×1, стоит на полу
  decorBox(8, 0, 8, 9, 1, 9),

  // колонна в углу
  decorBox(-11, 0, -11, -10, 6, -10),
];
```

Аргументы — мировые координаты двух углов: `minX, minY, minZ, maxX, maxY, maxZ`. Пол на `y = 0`, границы комнаты `±CONFIG.arena.halfExtent`.

Запусти `npm run dev` — на месте каждой записи появится коричневая коробка. Это заглушка, и она же показывает, где именно стоит препятствие.

## Когда появилась модель

Добавь флаг и положи модель, как в рецепте выше:

```ts
decorBox(8, 0, 8, 9, 1, 9, { invisible: true });
```

```ts
// src/app/Game.ts
void loadModel('/models/crate.glb').then((model) => {
  fitToBox(model, DECOR[0]);
  this.sceneRoot.scene.add(model);
});
```

## Ограничения коллизии, которые важно знать заранее

- **Коллизия только по AABB.** Никаких меш-коллайдеров и никаких поворотов: физика умеет только параллелепипеды, выровненные по осям. Повёрнутая модель обсчитается по прямоугольной коробке вокруг неё.
- **Сложную форму собирай из нескольких коробок.** Арка — это две стойки и перекладина, три записи в `DECOR`. Это дешевле и предсказуемее любого меш-коллайдера.
- **Коробки не должны пересекаться между собой.** Тест `solid boxes never overlap each other` в `tests/arena.test.ts` это проверяет. Касаться гранями можно, пересекаться нельзя.
- **Декорация может сломать проходимость.** Поставишь колонну вплотную к глыбе — часть её оболочки станет недостижимой, и победа не сработает никогда. Тест досягаемости упадёт со списком недостижимых точек. Это не придирка теста, это спасение от невыигрываемого уровня.
- **Не ставь декорации на настил лесов и в проход под ним.** Проход под настилом ровно в рост игрока, любой предмет там перекроет путь к низу глыбы.

## Декорация без коллизии

Если предмет чисто фоновый и проходить сквозь него не жалко — не заводи запись в `DECOR` вовсе. Загрузи модель и добавь в сцену:

```ts
void loadModel('/models/banner.glb').then((model) => {
  model.position.set(0, 4, -11.5);
  this.sceneRoot.scene.add(model);
});
```

Так дешевле: физика о таком предмете вообще не узнает.

# Часть 3. Текстуры

## Мрамор на глыбе

Текстура уже стоит: `assets/images/diorite.png`. Загрузка в `Game.buildLevel()`, юниформы `uMarbleMap` / `uHasMarbleMap` / `uMarbleScale` в `voxelMaterial.ts`, слот `VoxelRenderer.setMarbleMap`.

**Заменить картинку** — подмени файл или путь импорта в `Game.ts`. `colorSpace = THREE.SRGBColorSpace`, `RepeatWrapping`. Масштаб повтора — `uMarbleScale` (сейчас `1` на мировую единицу).

**UV — мировые, не на клетку.** По нормали грани берётся пара осей (`xz` сверху, `zy` / `xy` сбоку), поэтому соседние клетки продолжают один камень. UV грани куба (`vUv`) для мрамора не используются: на каждой клетке одна и та же картинка снова дала бы вид плитки. Затемнения рёбер в шейдере больше нет — границы клетки рисует только каркас прицела (`HighlightBox`).

`colors.marble` — запасной плоский цвет, если текстура не загрузилась. Скульптура текстуру не берёт: пока долбишь — `colors.sculpture`, после зачистки мрамора — RGB из `.vox` (см. `LevelAuthoring.md`). Повреждения поверх покраски: краснота, затемнение и трещины.

## Трещины

Атлас рисуется на canvas в `src/view/crackAtlas.ts`. Заменить на картинку можно, но контракт держать обязательно:

- **Раскладка:** `crackStages` плиток в ряд по горизонтали, одна строка. Ширина картинки = `stages × tileSize`, высота = `tileSize`.
- **Порядок:** слева направо от едва заметной трещины к сетке перед расколом.
- **Канал:** читается **красный**. Белое — трещина, чёрное — целый камень.
- **Фильтрация:** `NearestFilter` и `ClampToEdgeWrapping`, `colorSpace` не менять. Атлас читается как данные, а не как цвет: линейная фильтрация размажет соседние стадии друг в друга.

Замена — одна строка в `Game.buildLevel()`:

```ts
const atlas = new THREE.TextureLoader().load('/textures/cracks.png');
atlas.magFilter = THREE.NearestFilter;
atlas.minFilter = THREE.NearestFilter;
atlas.wrapS = THREE.ClampToEdgeWrapping;
atlas.wrapT = THREE.ClampToEdgeWrapping;
this.voxelRenderer.setCrackAtlas(atlas);
```

Число плиток обязано совпадать с `CONFIG.chisel.crackStages`. Не совпадёт — стадии поедут, увидишь чужие трещины.

## Пол, стены, декорации

Материалы блок-аута создаются по одному на коробку в `src/view/blockout.ts`, поэтому текстуру можно тайлить под размер каждой коробки:

```ts
const map = new THREE.TextureLoader().load('/textures/concrete.png');
map.wrapS = THREE.RepeatWrapping;
map.wrapT = THREE.RepeatWrapping;

const mesh = new THREE.Mesh(
  new THREE.BoxGeometry(width, height, depth),
  new THREE.MeshLambertMaterial({ color: COLORS[box.kind], map }),
);
```

Загружай текстуру **один раз вне цикла** и переиспользуй — иначе на каждую коробку уедет отдельная копия в памяти видеокарты. Повтор под размер коробки задаётся через `map.repeat`, но одна текстура на все коробки одним `repeat` не обойдётся: либо клонируй текстуру на каждый размер (`map.clone()`), либо смирись с растяжением.

## Осколки

Один материал на весь пул, `src/view/ShardFX.ts`. Цвет — `colors.shard` (чуть светлее и холоднее камня): Ламберт без шейдерного пола 0.45 из глыбы проваливал крошку в тень. Текстура на осколке почти не читается: он размером `0.44 × VOXEL` и живёт меньше секунды. Не трать на это время.

# Часть 4. Свет, фон, качество

Всё в `src/view/SceneRoot.ts`.

| Что | Сейчас | Как менять |
| --- | --- | --- |
| Полусферический свет | `0xffffff / 0x404048`, сила `0.7` | Прямо в конструкторе |
| Направленный свет | `0xffffff`, сила `0.8`, позиция `(1, 2, 1.5)` | Прямо в конструкторе |
| Свет на глыбе | Отдельный, `uLightDir` в шейдере | `src/view/voxelMaterial.ts` |
| Фон | Цвет `colors.background` | Для скайбокса — `scene.background = текстура` |
| Тени | Выключены | `renderer.shadowMap.enabled = true` + `castShadow`/`receiveShadow` на мешах |
| Пиксельная плотность | `min(devicePixelRatio, 2)` | Не поднимай выше 2, это удвоение цены кадра ни за что |
| Дальняя плоскость камеры | `200` | Хватает на комнату `24 × 24`; увеличивай только если появится далёкий фон |

Тени включать не спеши: сцена состоит из коробок и одного инстансного меша на несколько тысяч клеток, и карта теней от такого количества инстансов стоит дорого. Если включаешь — начни с одного направленного источника и небольшой карты.

# Проверка и частые ошибки

После любой правки сцены:

```
npm test          # коллизия и проходимость
npm run build     # типы и сборка
npm run dev       # глазами
```

| Симптом | Причина |
| --- | --- |
| Модель загрузилась, но её не видно | Не добавлена в `scene`, либо масштаб в метрах — умножь на 1.64 |
| Модель есть, но игрок проходит сквозь | Нет записи в `DECOR`. Модель сама по себе коллизии не даёт |
| Игрок упирается в пустоту | Коробка есть, а модель скрыта или не загрузилась. Убери `invisible`, чтобы увидеть препятствие |
| Модель лежит на боку | Ось вверх не Y. Разворачивай в редакторе, не в коде |
| Свет поменял всё, кроме глыбы | Так и есть: у глыбы свой шейдер, правь `uLightDir` |
| Трещины показывают не ту стадию | Число плиток в атласе не равно `CONFIG.chisel.crackStages` |
| Упал тест досягаемости | Декорация или потолок закрыли часть глыбы. Убери или отодвинь — иначе уровень непроходим |
| Упал `solid boxes never overlap` | Две коробки пересекаются. Касаться можно, пересекаться нет |
| Кадр просел после текстур | Текстура загружается внутри цикла по коробкам. Вынеси наружу |
