# Справочник по `src/config.ts`

**Кому:** тому, кто крутит числа игры. Отдельная модель, отдельная сессия, знать остальной проект не обязательно.
**Правило проекта:** все игровые числа живут только в `src/config.ts`. Магических констант в логике нет — если хочется добавить число в код, значит его место здесь.

## Как пользоваться

1. Найди параметр в таблицах ниже.
2. Посмотри столбец **Можно ли трогать**. Если там «нет» — не трогай, там есть объяснение почему.
3. Правь одно число за раз.
4. Прогони проверку: `npm test` — и только потом смотри в игре.

```
npm test          # ловит нарушенные инварианты раскладки и физики
npm run build     # типы и сборка
npm run dev       # посмотреть глазами
```

**Если `npm test` упал после правки конфига — это не «сломанный тест», это пойманная поломка уровня.** Верни число назад или читай раздел «Связки, которые нельзя нарушать».

## Единицы измерения

Их две, и путать их нельзя.

| Единица     | Что это                                                              | Где встречается                                |
| ----------- | -------------------------------------------------------------------- | ---------------------------------------------- |
| **Мировая** | Метры сцены Three.js. Пол арены — `y = 0`                            | Всё про игрока, арену, дальность руки, осколки |
| **Клетка**  | Одна воксельная клетка. Её сторона = `grid.voxelSize` мировых единиц | Только `grid.sizes` и внутренности домена      |

Масштаб сцены задаёт **игрок**, а не воксель. Рост игрока — мировая константа, и воксель можно дробить как угодно, ничего больше не пересчитывая. Обратное неверно: если выразить рост игрока через `VOXEL`, при следующем дроблении сетки игрок усохнет вместе с кубиками. Так уже было — не возвращай.

Полезные производные числа при текущем конфиге:

- Клетка: `0.25` мировых единиц.
- Глыба medium: `14 × 0.25 = 3.5` в ширину и глубину, `24 × 0.25 = 6` в высоту, стоит от `y = 0` до `y = 6`, центрирована по X и Z.
- Глыба small: `8 × 0.25 = 2` в ширину, `12 × 0.25 = 3` в высоту, `10 × 0.25 = 2.5` в глубину.
- Игрок: `2.95` в высоту — это почти 12 клеток. В ширину `0.95` — почти 4 клетки.
- Клеток в глыбе: `4704`, из них мрамора `4032`, скульптуры `672`.
- Слом одной клетки мрамора: `marbleHp / dps = 0.4` с. Клетки оригинала: `0.56` с.

## `grid` — сетка глыбы

| Параметр         | Сейчас          | Что делает                                                        | Можно ли трогать                                                                                           |
| ---------------- | --------------- | ----------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `sizes.medium`   | `[14, 24, 14]`  | Сетка `medium`-уровня, `[ширина, высота, глубина]`                | Да, но вместе с `chisel.marbleHp`, иначе уедет время сессии                                                |
| `sizes.small`    | `[8, 12, 10]`   | Сетка `small`-уровня                                              | Да. Чуть больше половины medium. Утка 6×9×8 закрыта клеткой мрамора с боков, спереди и сзади                |
| `voxelSize`      | `0.25`          | Сторона клетки в мире. Задаётся константой `VOXEL` в начале файла | Да. Чтобы глыба осталась того же размера, умножь числа в `sizes` во столько же раз, во сколько уменьшил `voxelSize` |

**Размер глыбы в мире** = `sizes[тип] × voxelSize` по каждой оси. Это то, что видит игрок. Число клеток в одиночку ничего не говорит. Тип уровня (`small` / `medium`) задаётся в `catalog.ts` и выбирает и сетку, и леса.

Ниже `7 × 12 × 7` не опускайся: процедурный крест задан долями габарита, и на совсем мелкой сетке мраморная скорлупа вокруг него истончается до нуля. Проверяется в `tests/crossLevel.test.ts`.

## `chisel` — долбёжка

| Параметр      | Сейчас | Что делает                            | Можно ли трогать                                                                                                                                                                               |
| ------------- | ------ | ------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `dps`         | `2.5`  | Урон в секунду при зажатой ЛКМ        | Да, но **не выше 4**: удержание превратится в «один тап», это запрещено §11 GDD                                                                                                                |
| `marbleHp`    | `1.0`  | Прочность клетки мрамора              | Да. Главный рычаг длины сессии                                                                                                                                                                 |
| `sculptureHp` | `1.4`  | Прочность клетки оригинала            | Да. Должна быть заметно больше мрамора: игрок обязан успеть отпустить кнопку                                                                                                                   |
| `crackStages` | `8`    | Сколько стадий трещин                 | Да, `4–10`. Атлас трещин и шейдер подхватывают число сами                                                                                                                                      |
| `reach`       | `3`    | Дальность руки в **мировых** единицах | Осторожно: увеличишь — верх глыбы станет достаться с земли, и леса потеряют смысл; уменьшишь — часть оболочки станет недосягаемой и победа не сработает никогда. Ломает инвариант досягаемости |

**Длина сессии** = `количество_мраморных_клеток × marbleHp / dps`. Победа требует снять весь мрамор, других рычагов нет. Сейчас это около 27 минут — известное расхождение с §11 GDD, разбор в `TechPlan.md` §3.2. Не «исправляй» его делением `marbleHp` на объём клетки: слом клетки уедет в 0.05 с, и от долбёжки останется невнятная струя крошки.

**Быстро добраться до зачистки нужно не через `dps`.** В меню по Esc есть отладка: тумблер «Ваншот» и кнопка «Оставить один воксель». После последней клетки мрамора фигура красится и можно ходить; экран оценки — снова по Esc. См. раздел «Отладка» ниже.

## `player` — игрок

Все числа **мировые**. Ни одно из них не выражай через `VOXEL`.

| Параметр       | Сейчас  | Что делает                           | Можно ли трогать                                                |
| -------------- | ------- | ------------------------------------ | --------------------------------------------------------------- |
| `width`        | `0.95`  | Сторона квадратного основания тела   | Осторожно: связан с проходимостью выдолбленных коридоров        |
| `height`       | `2.95`  | Полный рост                          | Осторожно: связан с проходом под настилом лесов                 |
| `eyeHeight`    | `2.7`   | Высота глаз от ног                   | Осторожно: вместе с `chisel.reach` задаёт досягаемость оболочки |
| `walkSpeed`    | `4.6`   | Скорость ходьбы                      | Да, свободно                                                    |
| `accel`        | `18`    | Разгон до `walkSpeed`                | Да, свободно                                                    |
| `gravity`      | `28`    | Ускорение падения                    | Да, но вместе с `jumpSpeed`                                     |
| `jumpSpeed`    | `8`     | Начальная скорость прыжка            | Да. Высота прыжка = `jumpSpeed² / (2 × gravity)`, сейчас `1.14` |
| `stepHeight`   | `0.525` | Уступ, который берётся автоматически | Да. Сейчас это чуть больше двух клеток                          |
| `maxFallSpeed` | `40`    | Предел скорости падения              | Да, свободно                                                    |
| `climbSpeed`   | `2.4`   | Скорость по лестнице                 | Да, свободно                                                    |
| `crouchScale`  | `0.5`   | Во сколько раз короче рост и глаза при приседе | Да, свободно                                              |

Числа роста и ширины нарочно не круглые (`2.95`, а не `3`). При точном совпадении с решёткой выдолбленный ровно в свой рост коридор не пропускал бы игрока: погрешность в один ULP задевает следующий слой клеток.

## `arena` — комната и леса

Все числа мировые. Схема: глыба в центре, вокруг пол и стены, с двух противоположных сторон глыбы — леса буквой «П».

| Параметр          | Сейчас  | Что делает                                           | Можно ли трогать                                                                    |
| ----------------- | ------- | ---------------------------------------------------- | ----------------------------------------------------------------------------------- |
| `halfExtent`      | `12`    | Полуразмер пола: комната `24 × 24`                   | Да, свободно. Это же границы, за которые игрока не выпускают                        |
| `deckTops`        | `[3.5]` | Верх настилов лесов, снизу вверх. Настил всего один  | Да, но см. связку «проход под настилом»                                             |
| `plateThickness`  | `0.25`  | Толщина плиты пола и настила                         | Да, осторожно: входит в проход под настилом                                         |
| `deckMargin`      | `0.5`   | Насколько настил шире глыбы с каждой стороны         | Да                                                                                  |
| `deckGap`         | `0.5`   | Зазор между гранью глыбы и настилом — «оффсет лесов» | Да, но большой зазор рвёт досягаемость: с настила перестанешь дотягиваться до глыбы |
| `deckDepth`       | `1.5`   | Глубина прохода по настилу                           | Да                                                                                  |
| `ladderThickness` | `0.3`   | Толщина боковых опор-лестниц                         | Да, свободно                                                                        |
| `wallThickness`   | `0.5`   | Толщина стен                                         | Да, свободно                                                                        |
| `wallTop`         | `12`    | Высота стен                                          | Да, но не ниже `max(deckTops) + player.height`, иначе с настила видно за стену      |

Что раскладка считает сама и в конфиге не лежит: ширина настила (`глыба + deckMargin`), высота опор (ровно до верха настила), точка спавна (перед лесами, лицом к глыбе), позиция глыбы (центр пола).

Подробные рецепты по лесам — в `LevelAuthoring.md`.

## Связки, которые нельзя нарушать

Четыре штуки. Каждую ловит тест, поэтому `npm test` после правки конфига обязателен.

### 1. Проход под настилом лесов

```
min(deckTops) - plateThickness  >  player.height
3.5 - 0.25 = 3.25 > 2.95        ✓ запас 0.3
```

Если сломать — к нижней части глыбы не подойти, и низ станет невыдалбливаемым. Ловит `tests/arena.test.ts`, тест `the player fits under the scaffold deck`.

Именно поэтому настил **один**. Второй ярус на удобной высоте перекрыл бы проход под первым.

### 2. Досягаемость всей оболочки глыбы

Связаны `chisel.reach`, `player.eyeHeight`, `deckTops`, `deckGap` и высота глыбы. Требование: до каждой внешней грани глыбы можно дотянуться хотя бы из одной позиции, где игрок физически может стоять. Дальше долбёжка идёт вглубь, то есть всегда ближе, поэтому оболочки достаточно.

Если сломать — какая-то клетка мрамора останется недостижимой, и **победа не сработает никогда**, а игрок не поймёт почему. Ловит `tests/arena.test.ts`, тесты `every glyba layer is within reach…` и `the whole outer shell…`.

### 3. Габариты игрока против решётки

`player.width` и `player.height` должны быть чуть меньше кратного `voxelSize`, иначе выдолбленный ровно в рост коридор не пропускает игрока. Ловит `tests/playerBody.test.ts`, тест `needs full height clearance…`.

### 4. Время сессии против прочности клетки

`количество_мраморных_клеток × marbleHp / dps`. Тестом не ловится — это баланс, а не поломка. Считай руками при каждой правке `grid.sizes` или `marbleHp`.

## Рецепты

| Хочу                                   | Правь                                             | Не забудь                                                           |
| -------------------------------------- | ------------------------------------------------- | ------------------------------------------------------------------- |
| Зерно мрамора мельче                   | `VOXEL` вниз, `grid.sizes` во столько же раз вверх | Габариты игрока не трогать. Пересчитать длину сессии                |
| Глыбу физически больше                 | нужный ключ в `grid.sizes` вверх при том же `VOXEL` | `deckTops`, `reach` и досягаемость. Сессия вырастет пропорционально |

| Леса дальше от глыбы                   | `deckGap`                                         | Связка 2                                                            |

## Отладка вместо правки чисел

Не трогай `dps` и `marbleHp`, чтобы «побыстрее посмотреть». В игре есть отладочное меню: нажми **Esc**, под кнопкой «Продолжить» появится блок «Отладка».

| Элемент                                       | Что делает                                                                                                                                                                                                       |
| --------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Тумблер **«Ваншот: мрамор с одного касания»** | Любая клетка мрамора рассыпается от первого касания. Оригинал держится как обычно — иначе случайный кадр по кресту испортит ровно ту оценку, ради которой уровень и прогоняют. Тумблер переживает рестарт уровня |
| Кнопка **«Оставить один воксель»**            | Снимает весь мрамор, кроме одной клетки — ближайшей к игроку. До зачистки остаётся одно касание, потом можно отойти и смотреть заказ; оценка — по Esc. Оригинал не трогает                                      |

Меню видно только в `npm run dev`: в собранной версии (`npm run build`) блок не монтируется. Если отладка нужна в сборке — убери проверку `import.meta.env.DEV` в конструкторе `src/app/Game.ts`.

Добавить свой тумблер: `src/ui/DebugMenu.ts` (разметка и колбэк), затем обработчик в `src/app/Game.ts`. Больше нигде ничего править не нужно.

## Чего в конфиге нет и быть не должно

- **Позиций конкретных объектов.** Раскладку арены считает `src/domain/levels/arena.ts` из параметров выше. Захардкодить координату настила — значит развалить связки.
- **Формы скульптуры.** Крест — `crossLevel.ts`, утка — `duckLevel.ts` и `assets/vox/duck.vox`. См. `LevelAuthoring.md`.
- **Путей к моделям и текстурам.** Мрамор сейчас `assets/images/diorite.png`. См. `SceneAuthoring.md`.
- **Констант шейдера.** Смешивание урона, масштаб текстуры мрамора и покраска из `.vox` живут в `src/view/voxelMaterial.ts`. Затемнения рёбер больше нет.
