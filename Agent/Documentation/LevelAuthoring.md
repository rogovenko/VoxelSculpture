# Уровень: фигура внутри глыбы и леса вокруг неё

**Кому:** тому, кто меняет скрытую скульптуру, разрешение сетки или геометрию лесов. Знать остальной проект не обязательно.
**Сюда не входит:** числа баланса (`ConfigReference.md`) и внешний вид — модели, текстуры, декорации (`SceneAuthoring.md`).

## Что вообще есть в уровне

Две независимые вещи:

1. **Глыба** — воксельная сетка. Часть клеток мрамор (долбятся), часть скульптура (не долбятся). Крест собирает `crossLevel.ts`, утку — `duckLevel.ts` из `assets/vox/duck.vox`.
2. **Арена** — пол, стены, леса. Не воксели, а список коробок. Её строит `src/domain/levels/arena.ts` из параметров `CONFIG.arena`.

Собирает их вместе `Game.buildLevel()` в `src/app/Game.ts`. Какой уровень грузить, решает каталог `src/domain/levels/catalog.ts` — он же рисует квадратики в стартовом меню.

## Команды проверки

После **любой** правки в этом документе:

```
npm test          # ловит нарушенные инварианты
npm run dev       # посмотреть глазами
```

Тесты здесь не формальность. Они проверяют две вещи, которые ломаются молча и делают уровень непроходимым: что скульптура полностью закрыта мрамором и что до каждой клетки оболочки можно дотянуться.

# Часть 1. Заменить фигуру внутри глыбы

## Как фигура задана сейчас

Предикатом: «эта клетка — часть скульптуры?». Всё, что не скульптура, автоматически становится мрамором.

```ts
// src/domain/levels/crossLevel.ts
return createShapeLevel('cross', size, (x, y, z) => {
  const inDepth = z >= stemZ0 && z <= stemZ1;
  const inStem = inDepth && x >= stemX0 && x <= stemX1 && y >= stemY0 && y <= stemY1;
  const inBar = inDepth && x >= barX0 && x <= barX1 && y >= barY0 && y <= barY1;
  return inStem || inBar;
});
```

Координаты — **целые номера клеток**, от `0` до `size - 1` по каждой оси. `x` — ширина, `y` — высота (вверх), `z` — глубина.

**Границы фигуры заданы долями габарита, а не числом клеток.** Это важно: `2 / 7` от ширины останется той же долей на любой сетке, а «3 клетки» на вдвое мельче сетке превратятся из перекладины в спицу. Функция `inset(доля, размер)` отсчитывает отступ одинаково с двух сторон, поэтому симметрия не зависит от округления.

## Рецепт: своя фигура

### Шаг 1. Новый файл

Создай `src/domain/levels/<имя>Level.ts` по образцу ниже. Крест не удаляй — он пригодится для сравнения.

```ts
import type { LevelData } from './LevelData';
import { createShapeLevel } from './shapeLevel';

// Доли габарита, а не числа клеток.
const BODY_INSET = 2 / 7;
const HEAD_BOTTOM = 3 / 4;

function inset(fraction: number, extent: number): [number, number] {
  const from = Math.round(fraction * extent);
  return [from, extent - 1 - from];
}

export function createPillarLevel(size: [number, number, number]): LevelData {
  const [sx, sy, sz] = size;
  const [x0, x1] = inset(BODY_INSET, sx);
  const [z0, z1] = inset(BODY_INSET, sz);
  const headY = Math.round(HEAD_BOTTOM * sy);

  return createShapeLevel('pillar', size, (x, y, z) => {
    const inColumn = x >= x0 && x <= x1 && z >= z0 && z <= z1;
    const inCap = y >= headY && y < sy - 2;
    return inColumn && (y >= 2 || inCap);
  });
}
```

### Шаг 2. Одна строка в каталоге

В `src/domain/levels/catalog.ts` добавь запись. Порядок в массиве — порядок квадратиков в стартовом меню:

```ts
import { createPillarLevel } from './pillarLevel';

export const LEVELS: readonly LevelDef[] = [
  { id: 'duck', number: 1, title: 'Утка', size: 'small', create: createDuckLevel },
  { id: 'pillar', number: 2, title: 'Колонна', size: 'medium', create: createPillarLevel },
];
```

`size` — `small` или `medium`. От него зависят две вещи: сетка глыбы (`CONFIG.grid.sizes`, сейчас `8×12×10` и `14×24×14`) и леса (только на `medium`).

Квадратики без фабрики (`create: null`) рисуются, но выбрать их нельзя — так сейчас стоит уровень 3. Сейчас в меню: 1 утка (`small`), 2 крест с лесами (`medium`). Меню само подхватит список, в `Game` ничего менять не нужно.

### Шаг 3. Проверить

```
npm test
npm run dev
```

В игре включи в меню по Esc тумблер «Ваншот» и снеси мрамор с одной стороны — фигура должна открыться целиком, без дыр наружу.

## Правила, которые фигура обязана соблюдать

Четыре. Первые два — жёсткие, уровень без них ломается.

1. **Скульптура не касается внешней оболочки глыбы.** Ни одна клетка скульптуры не может стоять при `x = 0`, `x = sx - 1`, `y = 0`, `y = sy - 1`, `z = 0`, `z = sz - 1`. Иначе она видна снаружи до первого удара, а по канону §4.1 GDD должна быть спрятана. Держи отступ минимум в одну клетку, лучше в две.
2. **Скульптура не должна стоять на воздухе.** Ни у одной её клетки в начале уровня не должно быть пустого соседа. Если предикат оставляет пустоты — это дыры в глыбе, игрок увидит их сразу.
3. **Мрамор должен быть весь достижим.** Победа требует снять весь мрамор. Внутренняя полость, замкнутая скульптурой, сделает уровень непроходимым. Простое правило: не строй фигуру, которая делит мрамор на несвязные куски.
4. **Симметрия желательна, но не обязательна.** Крест симметричен по X и Z, и тест это проверяет — для новой фигуры такой тест придётся написать или не проверять симметрию вовсе.

Первое и второе правило для креста проверяет `tests/crossLevel.test.ts`. **Для новой фигуры этих тестов нет** — либо скопируй файл теста под свою фигуру, либо проверь глазами по инструкции из шага 3. Если нужен готовый тест на новую фигуру — попроси, это отдельная небольшая задача.

## Рецепт: больше кубиков

«Больше кубиков» — это два разных желания, не путай их.

### Мельче зерно, глыба того же размера

Это то, что уже сделано дважды. Правишь `src/config.ts`:

```ts
const VOXEL = 0.125;                              // было 0.25
sizes: {
  small: [16, 24, 20],                            // было [8, 12, 10]
  medium: [28, 48, 28],                           // было [14, 24, 14]
},
```

Правило: **во сколько раз уменьшил `VOXEL`, во столько же увеличь каждое число в `sizes`.** Тогда `size × VOXEL` не изменится, и глыба останется прежней — мельче станет только зерно.

Что при этом произойдёт и о чём надо помнить:

- Клеток станет в 8 раз больше (в 2 раза по каждой оси). Полная зачистка станет в 8 раз дольше. Разбор и рычаги — в `TechPlan.md` §3.2.
- Габариты игрока, дальность руки и вся арена **не меняются**: они в мировых единицах. Ничего пересчитывать не надо.
- Фигура останется той же, потому что задана долями. Это и есть причина, по которой доли, а не клетки.
- `player.stepHeight` в клетках вырастет: тот же шаг в мире — это больше мелких клеток. Так и должно быть, длина ноги от зерна мрамора не зависит.

### Глыба физически больше

Правишь нужный ключ в `grid.sizes`, `VOXEL` не трогаешь:

```ts
medium: [20, 32, 20],   // глыба medium станет 5 × 8 × 5 мира
```

Тут придётся возиться, потому что меняется тело глыбы, а не зерно:

- **Высота лесов.** Глыба выросла вверх, до её верха с настила может не хватить руки. Поднимай `deckTops`.
- **Стены.** `wallTop` должен остаться выше `max(deckTops) + player.height`.
- **Досягаемость.** Именно её проверяет тест, и именно она отвалится первой.
- **Время сессии** вырастет пропорционально числу клеток.

Порядок работы: поправил `size` → `npm test` → тест досягаемости упал → поднял `deckTops` → снова `npm test`.

## Утка из MagicaVoxel

Источник фигуры — `assets/vox/duck.vox`. Плагин в `vite.config.ts` читает файл, перекладывает оси и разворачивает палитру в RGB. Сохранил в MagicaVoxel — обновил страницу, уровень подхватит новую модель. Парсер живёт в `src/domain/levels/vox.ts` и в бандл игры не попадает: в клиент уезжает уже готовый список клеток.

- **Ось вверх у нас Y, у MagicaVoxel — Z.** Пересчёт: размер `(mx, my, mz)` → `(mx, mz, my)`, клетка `(x, y, z)` → `(x, z, y)`. Сейчас в файле `6 8 9`, в игре это `6×9×8`. Сетка `small` — `8×12×10`, вокруг фигуры клетка мрамора с боков, спереди и сзади.
- **Пока долбишь, вся фигура одного цвета** (`colors.sculpture`). Когда мрамора не осталось, клетки берут RGB из палитры `.vox`. Повреждения не сбрасываются: поверх авторского цвета клетка краснеет, темнеет, и трещины возвращаются — в том числе на полностью добитых. На кресте палитры нет — он так и останется зелёным.
- **Пустая клетка в `.vox` — не дыра в глыбе.** Дырой она станет только если забыть дописать мрамор в `LevelData`; `createShapeLevel` как раз дописывает. Авторский цвет кладётся в необязательное поле `LevelData.paint`.
- Лапы ставятся на `y = 0` глыбы (пол). Это исключение из правила «скульптура не на оболочке» только по нижней грани: фигура сидит на полу, с боков и сверху скорлупа есть. По ширине и глубине модель центрируется. Если она больше сетки уровня, клетки снаружи просто не попадут в глыбу.
- После последней клетки мрамора можно ходить и смотреть заказ. Экран «Работа принята» открывается по **Esc**. Оценка фиксируется в кадр зачистки.
- `npm run export:duck` отключён: он затёр бы авторский `.vox`.

### Своя фигура из `.vox`

1. Положи файл в `assets/vox/<имя>.vox`.
2. Скопируй `duckLevel.ts`: импорт `*.vox`, множество клеток и `paint` из RGB, `createShapeLevel` с предикатом и четвёртым аргументом-цветом.
3. Добавь запись в `catalog.ts` (`small` или `medium`).
4. Сетка должна быть хотя бы на клетку шире модели по каждой оси, кроме пола, если фигура должна стоять на нём.

# Часть 2. Леса: высота и оффсет

## Как леса устроены

Двое лесов, с противоположных сторон глыбы по оси Z. Каждые — буква «П»: настил между двумя боковыми опорами-лестницами.

Вид сверху:

```
            x →
        ┌─┬────────────┬─┐   ← настил со стороны +z
        │L│   настил   │L│     L — опоры-лестницы, толщина ladderThickness
        └─┴────────────┴─┘
              ↕ deckGap
          ┌────────────┐
     z    │    глыба   │
     ↑    └────────────┘
     │        ↕ deckGap
     │  ┌─┬────────────┬─┐   ← настил со стороны -z
     │  │L│   настил   │L│
     └──┴─┴────────────┴─┘
```

Вид сбоку:

```
   ┌───────────┐  ← верх глыбы, y = size[1] × VOXEL
   │           │
   │   глыба   │   ┌────┐  ← deckTops[0], толщина plateThickness
   │           │   │    │
   │           │   │ L  │  ← под настилом проход в полный рост
───┴───────────┴───┴────┴───  y = 0, пол
                 ↑    ↑
             deckGap  deckDepth
```

Ширину настила, высоту опор и точку спавна раскладка считает сама. Опоры заканчиваются ровно на уровне настила, поэтому вся верхушка «П» — одна плоскость, и с последнего шага подъёма игрок оказывается на ней.

## Что чем правится

Всё в `CONFIG.arena` в `src/config.ts`.

| Хочу                          | Параметр             | Сейчас  |
| ----------------------------- | -------------------- | ------- |
| Настил выше или ниже          | `deckTops`           | `[3.5]` |
| Леса дальше от глыбы (оффсет) | `deckGap`            | `0.5`   |
| Настил шире глыбы с боков     | `deckMargin`         | `0.5`   |
| Проход по настилу глубже      | `deckDepth`          | `1.5`   |
| Опоры-лестницы толще          | `ladderThickness`    | `0.3`   |
| Второй ярус лесов             | `deckTops: [3.5, 7]` | —       |

## Два ограничения, и оба ловятся тестом

### Проход под настилом

```
min(deckTops) - plateThickness  >  player.height
```

Сейчас `3.5 - 0.25 = 3.25` против роста `2.95`. Если настил опустить — под него станет не пройти, и к нижней части глыбы не подобраться. Именно поэтому **настил один**: второй ярус на удобной высоте перекрыл бы проход под первым, и низ глыбы стал бы невыдалбливаемым.

Хочешь второй ярус — сначала убедись, что под первым остаётся полный рост, и что до верха глыбы с верхнего яруса не станет слишком далеко.

### Досягаемость оболочки

С настила и с земли вместе должно достаться до каждой внешней грани глыбы. Рвётся это тремя способами:

- поднял `deckTops` слишком высоко — не хватает руки до середины глыбы;
- опустил слишком низко — не хватает до верха;
- увеличил `deckGap` — с настила стало далеко до глыбы по горизонтали.

Если инвариант сломан, **победа не сработает никогда**: где-то останется клетка мрамора, до которой не дотянуться. Тест `tests/arena.test.ts` перебирает все внешние грани глыбы и все позиции, где игрок может стоять, и падает со списком недостижимых точек.

## Рецепт: поднять леса

1. Поменяй `deckTops: [3.5]` на нужную высоту.
2. `npm test`.
3. Упало `the player fits under the scaffold deck` — настил слишком низко, поднимай.
4. Упало `the whole outer shell of the glyba can be hit from somewhere` — читай список точек в ошибке. Метки вида `+y x7 z7` значат верхнюю грань, `+x y23 z7` — боковую на 23-м слое. Если недостижим верх, настил надо поднять; если середина — опустить.
5. Не сходится ни при какой высоте — значит нужен второй ярус (`deckTops: [3.5, 7]`) или больше `chisel.reach`.

## Чего в лесах нельзя делать

- **Лестница обязана оставаться сплошной.** Она в отдельном списке `ladders`, но в коллизию входит наравне со стенами. Сквозь неё не проходят; лазают, касаясь её снаружи. Односторонность подъёма — следствие геометрии «П», а не проверки в коде: изнутри подъём упирается в настил.
- **Не заводи второй список геометрии.** `arena.boxes` — одновременно и картинка, и коллизия. Второй список разъедется при первой правке, и игрок начнёт застревать в воздухе.
- **Не хардкодь координаты.** Всё считается из `CONFIG.arena`. Захардкоженная координата настила переживёт правку размера глыбы и окажется в неправильном месте.

## Полностью другая арена

Если нужна не «настил повыше», а другая схема лесов (например, спираль или леса с четырёх сторон), правится `createArena` в `src/domain/levels/arena.ts`. Требования к результату:

- `boxes` — все сплошные коробки, включая пол и стены;
- `ladders` — только то, по чему можно лазать;
- `walkTops` — верх каждой ходовой поверхности, снизу вверх, начиная с `0`;
- `spawn` — точка, где игрок не внутри геометрии и под ногами есть опора;
- `glybaMin` и `voxelSize` — не трогать, это перевод координат сетки в мир;
- `bounds` — границы, за которые игрока не выпускают.

Тесты в `tests/arena.test.ts` проверят непересечение коробок, спавн, замкнутость арены и досягаемость. Ориентируйся на них: если все зелёные, арена играбельна.
