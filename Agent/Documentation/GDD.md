# SculptureCraft — Game Design Document

**Рабочее название:** SculptureCraft  
**Жанр:** шуточный симулятор скульптора + incremental / clicker  
**Платформа прототипа:** браузер, JS/TS, WebGL  
**Версия документа:** 0.1.2 (концепт прототипа + принятые правки демки)  
**Язык:** русский  
**Статус:** канон для прототипа + предложения на будущее. Этот документ — исходник для последующей технической документации, не техспека.

**Куда идти за «как поменять»:** сначала `Agent/project.md` и skill из маршрутизатора. Этот файл — замысел, не инструкция к правке. Числа канона, если разошлись с кодом, зафиксированы в §11 и разобраны в `TechPlan.md` §3.2.

## 1. Видение

Игрок — не Микеланджело. Он человек с зубилом, которому сказали: _«скульптура уже внутри, просто убери лишнее»_.

**SculptureCraft** — упрощённый до кликера симулятор скульптора. Перед игроком стоит мраморная глыба из вокселей в два его роста. Внутри глыбы спрятана готовая форма. Задача игрока — выдолбить все лишние куски, не уничтожив (насколько получится) то, что внутри.

Основная механика разрушения взята из Minecraft: зажал левую кнопку — воксель покрывается трещинами — воксель исчезает. Это не головоломка «найди правильный порядок» и не песочница «лепи что хочешь». Это **долбёжка с прицелом**: скорость, аккуратность и жадность по апгрейдам.

Тон игры — шуточный. Серьёзный мрамор, студийный постамент, «высокое искусство» — и поверх этого кликерная петля «ещё чуть-чуть DPS». Для прототипа достаточно одной сцены и одного куска камня. Incremental-слой (апгрейды, уровни, сюжет) закладывается концептуально, но в прототип не входит.

## 2. Позиционирование

|                          |                                                                                                               |
| ------------------------ | ------------------------------------------------------------------------------------------------------------- |
| **Для кого**             | Любители incremental / clicker, которым нравится «цифра растёт», плюс лёгкий 3D-катарсис от откалывания камня |
| **Не для кого**          | Симулятор настоящего скульптора, voxel-редактор, Minecraft-клон                                               |
| **Фантазия игрока**      | Я отсекаю лишнее и из глыбы проступает статуя. Я могу работать грубо, но тогда «шедевр» будет в царапинах     |
| **Шутка**                | Искусство = DPS × время − штраф за попадание по оригиналу                                                     |
| **Фантазия incremental** | Зубило тупое → зубило острое → пневматика → подмастерья. Камень всё больше, статуи всё сложнее                |

Короткий питч: _Minecraft-ломание блоков встречает idle-кликер и музейный постамент. Выдолби Давида. Старайся не попасть по Давиду._

## 3. Область работ

### 3.1 Прототип (обязательно)

Сцена одна. Камера, прицел, долбёжка, осколки, оценка, рестарт. В демке два играбельных заказа: утка из MagicaVoxel (`small`, без лесов) и крест (`medium`, леса). Третий квадратик в меню — заглушка.

Окружение **не строить**: никакой мастерской, зала, реквизита, неба, пола «как в музее». Всё вокруг глыбы — максимально просто, из серых примитивов («коробок»). Бюджет внимания — на воксели и долбёжку.

Цель прототипа — проверить, что **кор приятен**: обойти глыбу, целиться в воксель, держать ЛКМ, смотреть как камень сыплется, увидеть фигуру, отойти и рассмотреть заказ, по Esc получить оценку.

### 3.2 Вне прототипа (не делать сейчас)

Апгрейды инструмента, магазин, несколько уровней, генерация скульптур, сюжет, престиж, автобой, инвентарь осколков, мультиплеер, сохранение прогресса между сессиями (кроме рестарта текущего уровня). Арт окружения: стены, окна, инструменты в кадре, детализированный постамент, освещение «студия / музей».

## 4. Сцена прототипа

### 4.1 Что видит игрок

Прямо на полу стоит **вытянутая вверх кубическая глыба** мрамора (классический блок для статуи) высотой примерно в два человеческих роста. Камера смотрит на глыбу. По центру экрана — перекрестье.

Саму сцену вокруг глыбы **не нужно строить**. Нет мастерской, колонн, окон, пола с текстурой, неба, реквизита. Всё — серые примитивы или вообще ничего. Прототип выглядит как серый блок-аут, не как локация.

Исключение появилось вместе с камерой от первого лица (§6.1): арене нужны пол, стены и **строительные леса**, иначе игроку негде стоять и не до чего дотянуться. Это по-прежнему серые коробки без деталей — геометрия существует ради досягаемости и коллизии, а не ради вида. Читается как леса вокруг статуи в работе, что тону только на пользу.

**История правки:** постамент из канона убран. Пока камера была орбитальной, он задавал «музейность», но с ногами он только отодвигал глыбу вверх, за пределы руки. Масштаб перенесён на игрока: сама глыба — в два его роста, а клетка мельче его примерно в двенадцать раз. Клетка при этом перестала быть «строительным блоком» и стала зерном камня: скол читается как работа резца, а не как выломанный куб.

Глыба собрана из вокселей (одинаковых кубиков). Часть вокселей — **мрамор** (можно уничтожить). Часть — **финальная скульптура** (уничтожить нельзя). Скульптура спрятана внутри глыбы: снаружи виден только светлый камень, пока игрок не откроет внутренние клетки.

Для прототипа финальная форма — **крест** (простая, сразу читаемая, хороша для проверки «нельзя сломать оригинал»).

### 4.2 Материалы (прототип)

| Тип вокселя           | Цвет                                                                 | Можно удалить  |
| --------------------- | -------------------------------------------------------------------- | -------------- |
| Мрамор (лишнее)       | Текстура камня (`diorite.png`); без неё — светло-серый               | Да, при HP = 0 |
| Скульптура (оригинал) | Пока долбишь — зелёный. После зачистки мрамора — цвета из `.vox`     | Нет            |

Мрамор должен выглядеть камнем, скульптура во время работы — «уже готовой вещью внутри». Контраст важнее реализма: игрок обязан понимать, куда бить нельзя, как только клетка открылась. Когда лишнего камня не осталось, заказ показывает авторскую покраску; царапины и трещины на нём остаются.

### 4.3 Постамент и окружение

Постамент не интерактивен. Это **серый ящик** под глыбой: масштаб и опора, чтобы камень не висел в воздухе. Не моделировать капители, ступени, таблички, орнамент.

Правило прототипа: **серые коробки + воксельная глыба**. Любая «студийность» — только в тоне текста UI, не в геометрии сцены.

## 5. Игровая петля прототипа

1. Игрок обходит глыбу и поднимается на леса, осматривая её с разных высот.
2. Ставит перекрестье на воксель мрамора.
3. Зажимает ЛКМ: воксель трещит, теряет HP, при нуле — разрушается с эффектом осколков.
4. Открываются соседние клетки; постепенно проступает зелёная фигура.
5. Если попал по скульптуре — она не исчезает, но краснеет (повреждение).
6. Когда лишнего мрамора не осталось — фигура красится в цвета заказа, ходить ещё можно. Оценка и «Заново» — по Esc.

Петля короткой сессии: _нашёл край → долбишь ряд → не задень зелёное → глыба худеет → статуя гола → смотришь → Esc → оценка._

## 6. Управление и камера

Управление нарочно простое. Игрок долбит туда, куда смотрит перекрестье, а не «кликает по пикселю модели» как в редакторе.

### 6.1 Камера

Камера **от первого лица**. Игрок ходит вокруг глыбы и долбит то, до чего дотягивается, как в Minecraft.

| Действие           | Управление              | Поведение                                               |
| ------------------ | ----------------------- | ------------------------------------------------------- |
| Обзор              | движение мыши           | Поворот головы, тангаж ограничен почти вертикалью       |
| Ходьба             | WASD                    | Перемещение относительно направления взгляда            |
| Прыжок             | Space                   | Только с опоры, на лестнице не действует                |
| Присед             | C (удерживать)          | Рост и глаза вдвое ниже; под низким потолком сам не встанет |
| Подъём по лестнице | «вперёд» вплотную к ней | Тем же нажатием прижимаешься, поэтому хват не срывается |
| Спуск по лестнице  | Shift на лестнице       | Отдельная кнопка: «назад» отодвинуло бы от лестницы     |
| Шире обзор         | ПКМ (удерживать)        | Плавно растёт FOV; отпустил — вернулось к рабочему      |

**Канон прототипа по ПКМ:** правая кнопка не отъезжает камерой — от ног игрока отъезжать некуда, — а расширяет угол обзора. Жест читается так же: «отошёл от станка, посмотрел на работу».

**Леса.** Наверх ведут **строительные леса с двух противоположных сторон** глыбы, стоящие чуть в стороне от неё. Каждые леса — буква «П»: настил выше роста игрока и две боковые опоры-лестницы от пола до настила. Лестница **сплошная**, сквозь неё не пройти, и работает только снаружи: подошёл вплотную, держишь «вперёд» — лезешь, и это же нажатие на верхушке само переносит тебя на настил, потому что опора заканчивается ровно его уровнем. Изнутри, из-под настила, залезть нельзя — подъём упирается в настил, и это нормально. Вниз — держишь спуск. Ничего не жмёшь — висишь. Лестница **выделена сиреневым**: это единственный цветной элемент блокаута, потому что единственный, с которым игрок взаимодействует.

С настила можно упасть, перил нет. Падение ничем не наказывается: игрок просто идёт обратно к лестнице.

Двух сторон достаточно намеренно: до дальней половины верхней грани с одних лесов не дотянуться, а с противоположных — уже да, и вместе они покрывают всю оболочку глыбы (инвариант проверяется тестом).

Ограничения:

- Игрок не проходит сквозь мрамор, скульптуру и серый блокаут, но может встать на них и войти в выдолбленную полость.
- Габариты игрока — примерно **12 вокселей в высоту и 4 в ширину**, поэтому в щель или коридор в один воксель он не просачивается: чтобы залезть внутрь глыбы, полость надо выдолбить в свой рост.
- Подъём **на пару вокселей** автоматический, выше — прыжком или по лестнице. Шаг задан длиной ноги, а не зерном сетки, поэтому в клетках он меняется вместе с разрешением.
- Под настилом лесов проход остаётся: настил висит выше роста игрока, иначе к низу глыбы было бы не подойти.
- Арена закрыта стенами: выпасть в пустоту нельзя.
- Дальность руки ограничена (§6.2), поэтому до верха глыбы надо подниматься на леса.

**История правки:** до первой игровой сборки каноном была орбитальная камера вокруг центра глыбы с отъездом по ПКМ. На практике целиться орбитой оказалось неудобно, поэтому схема сменена на перемещение от первого лица. Первая реализация подъёма — сплошные галереи-этажи со ступенями — оказалась лишней декорацией на пол-арены; её заменили компактные леса с лестницей.

### 6.2 Прицел и долбёжка

По центру экрана — **перекрестье** (простое, контрастное, как в шутере / Minecraft).

**ЛКМ по вокселю** = луч из центра экрана через перекрестье. Если луч попал в воксель — начинается (или продолжается) разрушение этой клетки.

- Нужно **удерживать** ЛКМ.
- Пока луч держится на том же вокселе — копится урон.
- Одновременно долбится только один воксель — тот, на который смотрит перекрестье.
- **Урон необратим.** Отпустил кнопку, сдвинул прицел, отошёл — накопленные HP и трещины остаются на клетке. Вернулся через минуту — продолжаешь с того же места.

**История правки:** сначала прогресс сбрасывался при отпускании ЛКМ или смене цели, как ломание блока в Minecraft. Для камня это выглядело неправдоподобно: настоящий скол не зарастает. Правило снято — теперь трещины на глыбе это карта уже сделанной работы, и долбить большую клетку можно с перерывами.

### 6.3 Наведение (highlight)

Если луч из перекрестья попадает в воксель — у этой клетки рисуется **чёрный каркас баундбокса** (рёбра куба), как рамка блока в Minecraft. Подсветка следует за прицелом мгновенно. Если прицел в пустоту — рамки нет.

Рамка рисуется и на мраморе, и на скульптуре: игрок должен видеть, _во что_ он сейчас ударит, в том числе когда целится в зелёное.

## 7. Воксели и разрушение

### 7.1 Сетка

Глыба — регулярная 3D-сетка одинаковых кубов. Для прототипа форма глыбы: **прямоугольный столб**, выше, чем шире и глубже (классический блок статуи). Точные размеры сетки — на этап техдока; ориентир: достаточно клеток, чтобы крест был узнаваем и вокруг него оставался «запас» мрамора, который нужно снять.

Пустые клетки (уже выдолбленные) — воздух, через них луч летит дальше до первого непрозрачного вокселя.

### 7.2 Два типа клеток

**Мрамор (лишнее)**

- Светлый.
- Есть HP.
- При HP ≤ 0 клетка удаляется из сетки.
- После удаления может открыться сосед (мрамор или скульптура).

**Скульптура (оригинал)**

- Зелёная.
- Есть HP (полоска «сохранности»).
- При HP ≤ 0 **не удаляется**.
- Визуально становится красной (повреждённый оригинал).
- Дальнейшие удары по уже красной клетке не меняют геометрию; урон в оценку уже засчитан (детали — §9).

Игрок не может «передумать» и восстановить мрамор. Прототип без отмены удара.

### 7.3 Урон

У игрока есть **урон в секунду** (DPS). У вокселя есть **очки прочности** (HP).

```
время_разрушения = HP_вокселя / DPS_игрока
```

Пока ЛКМ зажата и прицел на клетке, каждый кадр вычитается `DPS * dt`.

Для прототипа:

- Все мраморные клетки имеют одинаковый HP.
- Все клетки скульптуры имеют одинаковый HP (может совпадать с мрамором или быть выше — чтобы «ой» было заметно, но не мгновенно).
- DPS игрока константа, без апгрейдов.

### 7.4 Трещины

Пока клетка теряет HP, по её граням / поверхности показывается **прогресс разрушения** — стадии трещин, как в Minecraft (от едва заметных до сетки перед расколом).

Трещины:

- привязаны к вокселю, а не к прицелу, и остаются на нём после отпускания ЛКМ (§6.2);
- на скульптуре тоже показываются, пока её «сохранность» падает; после полного «убийства» HP клетка остаётся красной, трещины можно убрать (она уже «добита», но стоит).

### 7.5 Осколки

При разрушении мраморного вокселя от него **отлетают кусочки**. Это только эффект: подбирать нельзя, инвентаря нет, физика осколков не геймплей.

Допустимы частицы, мелкие меши с короткой жизнью, или гибрид. Требования к ощущению:

- кусок _откололся_, а не просто исчез;
- осколки разлетаются наружу / вниз и быстро пропадают;
- эффект лёгкий, не мешает целиться в следующий блок.

Удар по скульптуре (клетка не исчезла): мелкий эффект «пыль / искры», без полного разлёта кусков — оригинал не крошится в воздух.

## 8. Победа, оценка, рестарт

### 8.1 Условие победы

Условие зачистки — **в сетке не осталось ни одного мраморного вокселя**. На полу стоит фигура: если у уровня есть палитра `.vox`, она красится в эти цвета, повреждения (краснота и трещины) остаются. Экран оценки **не всплывает в этот кадр**: игрок может отойти и осмотреть заказ. «Работа принята» открывается по **Esc** (или любой потере pointer lock). Время сессии фиксируется в кадр последней клетки мрамора, осмотр его не растягивает.

Поражение в прототипе **нет**: скульптуру нельзя снести, уровень нельзя провалить по HP. Можно только сделать работу хуже и дольше.

### 8.2 Что считается

На победном экране:

1. **Повреждение оригинала** — насколько пострадала скрытая скульптура (доля клеток, доведённых до красного / средний остаток HP по клеткам оригинала).
2. **Снято мрамора** — сколько лишних блоков уничтожено (для прототипа это, по сути, 100% лишнего; цифра всё равно нужна как «работа сделана» и как заготовка под будущие цели).
3. **Время** — от первого удара до кадра зачистки последней клетки мрамора (не до нажатия Esc).

После цифр — предложение **начать уровень заново**. Выбор другого заказа — со стартового экрана.

### 8.3 Тон оценки (прототип)

Цифры важнее таблицы разрядов, но шуточный вердикт желателен, чтобы экран не был сухой статистикой. Пример шкалы (можно упростить до одной фразы):

| Повреждение оригинала         | Вердикт                                   |
| ----------------------------- | ----------------------------------------- |
| 0 клеток доведено до красного | «Микеланджело нервно курит в стороне»     |
| Малая доля                    | «Музей возьмёт, но реставратор проклянёт» |
| Большая доля                  | «Это уже современное искусство»           |
| Все клетки оригинала красные  | «Крест получился. Эмоционально»           |

Время можно комментировать отдельно («быстрый, но страшный» / «медленный перфекционист»), не обязательно в прототипе.

## 9. HUD и обратная связь

Минимальный интерфейс:

- Перекрестье в центре.
- Каркас вокселя под прицелом.
- Трещины на долбящейся клетке.
- (Опционально для прототипа) тонкий индикатор прогресса удара — не обязателен, если трещины читаются.
- Победа: оверлей со статистикой и кнопкой «Заново».

Не нужно в прототипе: хотбар, инвентарь, дерево апгрейдов, миникарта, здоровье игрока.

Обратная связь удара: смена трещин каждый кадр прогресса, звук удара по камню (если будут аудиоассеты), вспышка осколков в момент слома. Экранный шейк — по желанию, слабый.

## 10. Аудио (прототип, по возможности)

Не блокер, но сильно усиливает «minecraft-clicker» катарсис:

- зацикленный / ритмичный _тук_ пока держится ЛКМ;
- более жирный _крэк_ в момент слома мрамора;
- короткий неприятный _чик_ при ударе по скульптуре;
- тишина или лёгкий студийный эмбиент.

Если звуков в первой сборке не будет — кор всё равно должен читаться визуально.

## 11. Черновые числа прототипа

Числа ниже — **ориентиры**, не баланс-библия. Их можно сменить в техдоке, сохранив соотношения.

| Параметр              | Ориентир                                                     | Зачем                                                                                               |
| --------------------- | ------------------------------------------------------------ | --------------------------------------------------------------------------------------------------- |
| Сетка глыбы           | 14×14×24                                                     | Тело то же, что у прежних 7×7×12: воксель вдвое мельче, клеток в восемь раз больше                  |
| HP мрамора            | 1.0 усл. ед.                                                 | Базовая клетка. При дроблении вокселя **не** уменьшается: слом отдельной клетки важнее длины сессии |
| DPS игрока            | ~1.2–2.5 ед./сек                                             | Слом за ~0.4–0.8 с, как «подержать и отколоть», не автоклик одним тапом                             |
| Стадии трещин         | 4–10 шагов                                                   | Как Minecraft, дискретные кадры                                                                     |
| HP клетки скульптуры  | 1.0–1.5                                                      | Успеть понять, что бьёшь не туда, и отпустить                                                       |
| Жизнь осколков        | 0.4–0.8 с                                                    | Не засорять кадр                                                                                    |
| Размер осколка        | ~1/2 вокселя                                                 | Осколок — обломок клетки, поэтому мельчает вместе с ней                                             |
| Размер вокселя        | ~1/12 роста игрока                                           | Зерно мрамора, а не строительный блок: сколы читаются как работа резца                              |
| Габариты игрока       | 12 вокселей в высоту, 4 в ширину                             | В щель в один воксель не пролезть                                                                   |
| Дальность руки        | ~12 вокселей                                                 | Долбить только то, до чего дошёл ногами; верх глыбы с земли недосягаем                              |
| Высота настила лесов  | верхние слои глыбы в руке, под настилом проход в полный рост | Иначе либо верх недосягаем, либо низ                                                                |
| Расширение FOV по ПКМ | обзорный угол вместо рабочего                                | Осмотр работы                                                                                       |

Сессия прототипа: **примерно 1–3 минуты** аккуратной игры, быстрее если лупить без разбора.

**Известное расхождение.** С мелким вокселем эти 1–3 минуты и «слом за 0.4–0.8 с» одновременно недостижимы: клеток в глыбе стало в восемь раз больше, а победа требует снять весь мрамор (§8.1), то есть полная зачистка тянется десятки минут. Выбор сделан в пользу ощущения отдельной клетки. Правильный рычаг против длины сессии — не прочность камня, а **резец, который берёт несколько клеток за раз** (§12.7), либо честное «победа не по последней клетке». До этого сессию считать ориентиром для тюнинга, а не обещанием.

## 12. Предложения по улучшению концепта

Ниже — не скоуп прототипа, а усиление фантазии. Канон §§1–11 можно собирать без этого. Имеет смысл заложить в архитектуру то, что дешево (луч из центра, DPS как число, типы вокселей, событие «клетка сломана»).

### 12.1 Усилить шутку, не ломая кор

Сейчас игра уже смешная: высокое искусство сводится к DPS. Это можно сделать явным тоном UI: «Мастерская», «Заказ №1: Крест», победный акт экспертизы музея. Incremental потом продолжает шутку: «научный прогресс в области долбления».

Не стоит уходить в цинизм, где статуя — только HP-бар. Пусть зелёный крест всё-таки _красиво_ проступает из белого камня: в этом катарсис.

### 12.2 Камера: два режима яснее

**Устарело после перехода на камеру от первого лица (§6.1).** Раздел сохранён, потому что объясняет, откуда взялась и почему снята одна конкретная механика.

Изначально предлагалось: рабочий режим — ближняя орбита мышью, ПКМ — отъезд «отступить и посмотреть на работу», а на случай, если свободная мышь будет крутить камеру слишком нервно во время прицеливания, — **заморозка камеры при зажатой ЛКМ**, чтобы прицел не уезжал во время удара.

От первого лица эта заморозка вредна: невозможность повернуть голову во время долбёжки — просто поломанное управление, а конфликта «целюсь и одновременно уезжает орбита» больше нет, потому что взгляд и прицел — это одно и то же. Поэтому обзор мышью работает всегда, а ПКМ расширяет FOV вместо отъезда.

Что из раздела осталось в силе: жест ПКМ должен быть **плавным** и менять FOV, чтобы мозг читал его как «отошёл от станка».

### 12.3 «Скульптура краснеет» как шкала, не как бинар

Сейчас: HP → красный. Выразительнее промежуточный цвет: зелёный → желтоватый → алый по мере падения HP. Тогда игрок видит _царапину_, а не только финальный брак. Для оценки можно считать и частичный урон, не только «доведён до нуля».

### 12.4 Оценка, которая кормит incremental

Три метрики прототипа (урон оригиналу, блоки, время) — правильное зерно. Для жанра лучше сразу думать о **звёздах / ранге**, который потом открывает апгрейды:

- **Чистота** — не бить оригинал (главный скилл).
- **Скорость** — DPS и руки.
- **Объём** — сколько камня снято (на будущих уровнях не весь камень обязателен? или гонка «снять N блоков»).

Для _этого_ прототипа условие «снять весь лишний мрамор» оставляем. В расширенной версии можно добавить заказы вида «достаточно открыть силуэт» / лимит времени / лимит ударов по оригиналу.

### 12.5 Ощущение инструмента

Кликер живёт от фидбека. Даже без апгрейдов: лёгкий kick камеры на слом, пыль, смена тона удара когда под прицелом зелёное (предупреждение). Это дешевле контента и делает кор «дороже».

### 12.6 Крест — хороший прототип, плохой единственный контент

Крест идеален для проверки сетки (ось + перекладина, симметрия, внутренние пустоты). Следующие формы должны быть **узнаваемыми силуэтами** из вокселей: гриб, меч, человечек, чашка. В демке первый заказ уже такой — утка из MagicaVoxel, крест с лесами идёт вторым. Incremental живёт разнообразием «заказа», а не одним DPS.

### 12.7 Будущий idle не должен убить прицел

Опасность жанра: авто-долбёжка сделает 3D-сцену заставкой. Лучше раскладывать прогресс так:

- апгрейды ускоряют **ручной** удар (толщина зубила, AOE 1×1 → 2×1 «полоска», сквозной удар);
- авто-подмастерье бьёт **медленно и глупо**, иногда по оригиналу — шутка и повод не уходить в чистый idle;
- престиж «выставка» — галерея статуй с их рангом чистоты.

Так 3D-навык остаётся ядром, а цифры растут вокруг него.

### 12.8 Наведение на невидимое

Пока скульптура внутри, игрок бьёт вслепую. Для прототипа это ок: крест маленький, можно ошибиться. На сложных уровнях стоит слой подсказки: слабый «призрак» формы по ПКМ-осмотру, чертёж заказа в углу, или подсветка «здесь уже оригинал» только для открытых граней. Иначе поздние уровни превратятся в лотерею.

### 12.9 Физика глыбы

Не обязательно, но красиво: отколотый край даёт неровный силуэт, студийный свет читает ступеньки вокселей. Не скруглять меш в прототипе — воксельный Minecraft-характер это фича, не баг.

## 13. Расширенная версия (задел, не скоуп)

Имеет смысл держать в голове, чтобы прототип не закрыл двери.

| Слой        | Идея                                                                                    |
| ----------- | --------------------------------------------------------------------------------------- |
| Инструменты | Зубило, кирка, сверло, «неловкий динамит» (AOE, риск для оригинала)                     |
| Апгрейды    | DPS, скорость камеры, подсветка оригинала, щит «первый удар по скульптуре игнорируется» |
| Уровни      | Новые глыбы и силуэты, больше камня, тверже мрамор                                      |
| Сюжет       | Заказы абсурдного музея / капризного патрона                                            |
| Престиж     | Выставка, критики, множитель «репутация»                                                |
| Риск        | Случайные жилы, хрупкий камень рядом с оригиналом                                       |
| Мета        | Стартовый DPS крошечный, «ещё один удар» хочется всю сессию                             |

Прототип доказывает одно: **приятно отсекать лишнее от воксельной глыбы и страшно попасть по зелёному.**

## 14. Что должно остаться неизменным

1. Воксельная глыба, внутри скрытая скульптура.
2. Лишнее уничтожается, оригинал — нет.
3. Разрушение удерживанием, трещины, HP vs DPS.
4. Орбита вокруг работы, перекрестье, каркас блока.
5. Осколки — только VFX.
6. Победа = мрамора не осталось; оценка повреждения / объёма / времени; рестарт.
7. Тон — шуточный симулятор, цифры — incremental-задел.
8. Сцена вокруг глыбы не строится: серый блок-аут из коробок, без локации.
